# Weekly brief

## Gather

- `get_finance_summary` and `get_finance_trends` — revenue, outstanding, spend.
- `list_records` on deals and invoices — what moved, what did not.
- `list_positions` and `search_candidates` — open roles and who is in flight.
- `get_site_stats` — traffic, if the workspace has a site connected.

Ask for all of it before writing anything. A brief assembled section by section
ends up describing the tools rather than the week.

## Write

Six bullets, hard limit. Each one: the number, the direction, and why it
matters. "Outstanding is 48,200, up 9,600, all of it one invoice now 40 days
late" is a briefing. "Outstanding: 48,200" is a dashboard, and they already
have one.

Lead with what changed, not with what is largest. The largest number is the
same every week.

## The rules that make it trustworthy

**Never fill a gap with an estimate.** If a tool returned nothing, the line is
"no data for X this week". A brief with an invented figure in it is worse than
no brief, because nobody can tell which figure it was.

**A partial month is not a trend.** Comparing eleven days against a full month
makes every metric look like a collapse. Either compare like periods or say the
current one is incomplete.

**Do not congratulate.** No "great progress!". Report the week; the reader
decides how it went.
